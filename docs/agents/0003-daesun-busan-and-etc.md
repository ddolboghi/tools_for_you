# PRD: 부산 항목 추가와 기타 항목 체계화

## 배경

좋은데이 판촉 근무자는 야간 판촉 후 상권별 음용비를 집계하고, 상권 톡방과 담당자에게 각각 보고문을 보냅니다. 대선주조의 부산을 따로 집계해야 하는데 지금은 입력 칸이 없어, 근무자가 부산 테이블을 대선(C1포함) 숫자에 섞어 세어 왔습니다.

이 요청이 부산 한 줄로 끝나지 않는 이유는 두 가지입니다.

첫째, 부산을 분리하면 대선(C1포함) 숫자가 이전보다 작아집니다. 담당자 보고문이 대선 줄만 싣고 부산 줄을 싣지 않으면, 담당자에게는 대선 실적이 떨어진 것으로 읽힙니다. 줄어든 이유가 보고문 어디에도 없습니다.

둘째, 지금 데이터 프레임에는 기타 항목이 하이트진로와 대선주조에만 있고 무학과 롯데에는 없습니다. 그래서 무학이나 롯데의 집계 대상 밖 주류를 마시던 테이블은 어디에도 들어가지 못합니다. 게다가 네 회사에 속하지 않는 회사의 주류를 받는 `마. 기타`는 데이터가 아니라 하드코딩된 `마. 기타: 0t (0%)` 문자열이라 값이 언제나 0입니다. 총 테이블 수와 100% 보정에도 참여하지 못합니다.

모히또 작업(`0001-muhak-mojito.md` R2)에서 상권 보고문을 데이터 프레임 순회로 바꿔 두었기 때문에, 데이터 프레임에 항목을 더하면 입력 폼·화면 결과·백분율 계산·상권 보고문이 자동으로 따라옵니다. 손으로 손봐야 하는 곳은 하드코딩이 남아 있는 두 군데, 즉 `마. 기타` 줄과 담당자 보고문의 타사 큐레이션 목록입니다.

## 용어

[CONTEXT.md](../../CONTEXT.md)의 용어를 따릅니다. 이번 상의에서 **부산**, **기타**, **기타 주류회사** 세 항목이 글로서리에 추가되었으며, 그 편집은 이 PRD와 함께 커밋됩니다.

## 요구사항

### R1. 부산을 대선주조의 집계 항목으로 추가

- MUST: 데이터 프레임의 `"다. 대선주조"` 아래에 `부산`을 추가한다.
- MUST: 부산은 `대선(C1포함)` 다음, `기타` 앞에 온다.
- MUST: 부산은 대선(C1포함)에 합산되지 않는 독립 항목이다.
- 근거: 지금까지 부산 테이블이 대선(C1포함)에 섞여 있었다. 보고문에서 둘이 나란히 놓이면 분리된 경계가 읽는 사람에게 바로 보인다.

### R2. 모든 회사에 기타 항목을 둔다

- MUST: `"가. 무학"`과 `"라. 롯데"`에 `기타`를 추가한다. 하이트진로와 대선주조에는 이미 있으므로 손대지 않는다.
- MUST: 기타는 회사 안에서 마지막에 온다. 즉 무학은 좋은데이·모히또·톡시리즈·부산갈매기·기타, 롯데는 새로·청하(별빛청하 포함)·기타 순이다.
- 근거: 집계 대상 밖 주류를 마시던 테이블이 갈 곳이 없으면 그 테이블은 세어지지 않고 사라진다. 마지막 자리는 하이트진로와 대선주조에 이미 자리 잡은 방식이다.

### R3. `마. 기타 주류회사`를 데이터 프레임의 회사로 승격

- MUST: 데이터 프레임에 `"마. 기타 주류회사"`를 마지막 회사로 추가한다. 그 아래에는 항목 하나만 두고 이름은 `기타`로 한다.
- MUST: `utils/sale/report.ts`의 하드코딩된 `마. 기타: 0t (0%)` 줄과 `components/sale/Result.tsx`의 같은 줄을 삭제한다. 이 줄은 데이터 순회의 결과로 대체된다.
- MUST: 상권 보고문과 화면 결과에서, 항목이 정확히 하나인 회사는 회사 줄만 출력하고 항목 줄은 생략한다. 즉 `마. 기타 주류회사: 3T (3%)` 한 줄로 끝나고 `  - 기타: 3T (3%)`는 나오지 않는다.
- MUST: 항목 줄 생략은 항목 개수로 판정한다. 회사 이름이나 항목 이름으로 특별 취급하지 않는다.
- MUST: 입력 화면에서, 항목이 정확히 하나인 회사는 섹션 제목 오른쪽 같은 줄에 입력 칸을 놓는다. 항목 이름은 표시하지 않는다.
- MUST: 마의 테이블 수는 총 테이블 수에 더해지고 100% 보정에 참여한다.
- 근거: 항목이 하나면 회사 합계와 그 항목의 값이 언제나 같아 두 줄이 중복이다. 판정을 개수로 두면 나중에 마 아래에 항목이 늘어도 규칙이 저절로 맞고, 회사 이름을 조건에 박아 넣는 특별 취급이 남지 않는다. 하드코딩이던 마가 실제 값을 받게 되는 것이 이 요구사항의 핵심이며, 그래서 총합과 보정에 참여해야 한다.

### R4. 상권 보고문의 테이블 단위 표기를 대문자 T로 통일

- MUST: 상권 보고문의 소문자 `t`를 전부 대문자 `T`로 바꾼다. 회사 줄, 항목 줄, `총 테이블 수` 줄이 모두 해당한다.
- MUST: 화면 결과(`components/sale/Result.tsx`)의 같은 자리도 함께 바꾼다. 복사 텍스트와 화면이 어긋나면 안 된다.
- MUST: 입력 폼에서 입력 칸 뒤에 붙는 단위 표시도 `T`로 바꾼다.
- MUST: 담당자 보고문은 이미 대문자 `T`를 쓰므로 손대지 않는다.
- 근거: 담당자 보고문이 이미 T를 쓰는데 상권 보고문만 t였다. 한 도구가 내보내는 두 보고문의 표기를 통일한다. 한 보고문 안에 두 표기가 섞이면 합계 줄과 항목 줄이 다른 단위처럼 보인다.

### R5. 담당자 보고문에 부산 줄을 추가하고 기타를 전부 배제

- MUST: 담당자 보고문에 `부산 : ` 줄을 추가한다. 자리는 `대선(C1포함) : ` 바로 다음이다.
- MUST: 라벨은 이웃한 대선 줄의 표기를 따라 콜론 앞에 공백을 둔 `"부산 : "`으로 한다.
- MUST: 부산 줄은 자기 항목의 테이블 수와 백분율을 그대로 싣는다. 대선(C1포함)과 합산하지 않으며, 어느 줄에서도 새로 백분율을 계산하지 않는다.
- MUST: 어느 회사의 `기타`도 담당자 보고문에 싣지 않는다. 무학은 데이터 프레임 전부를 순회하던 규칙에 기타 제외를 더하고, 타사는 큐레이션 목록에 없으므로 그대로 빠진다.
- MUST: `마. 기타 주류회사`는 담당자 보고문에 나오지 않는다.
- MUST: 진로·참이슬·새로·청하(별빛청하 포함) 줄의 문구와 순서는 지금 그대로 둔다.
- 근거: 부산을 분리하면 대선 숫자가 작아지는데, 부산 줄이 바로 아래 있으면 그 이유가 보고문 안에서 설명된다. 담당자 보고문은 주요 주류를 추려 싣는 큐레이션이고 기타는 주류가 아니라 잔여 항목이므로, 무학이든 타사든 같은 이유로 뺀다. 백분율을 새로 계산하지 않는 것은 항목별 백분율이 이미 100% 보정을 거친 값이라, 재계산하면 같은 밤의 상권 보고문과 어긋나기 때문이다. 측정 결과 표본 30,000건 중 35.7%에서 0.1~0.3%p 차이가 났다.

### R6. 출력 변화를 명시된 것으로 한정

- MUST: 새 항목(무학 기타, 대선주조 부산, 롯데 기타, 마 기타 주류회사)을 모두 0으로 둔 상태에서, 상권 보고문은 변경 전과 비교해 다음 세 가지만 달라야 한다.
  1. 소문자 `t`가 대문자 `T`로 바뀐다
  2. 새 항목 줄 세 개가 각 회사의 마지막에 추가된다
  3. `마. 기타: 0t (0%)`가 `마. 기타 주류회사: 0T (0%)`로 바뀐다
- MUST: 회사 사이 빈 줄, 항목 앞 공백 두 칸, 2번 항목 이후 전체는 글자 단위로 동일하다.
- 근거: 하드코딩 줄을 데이터 순회로 옮기는 변경은 눈에 안 보이는 공백 차이를 만들기 쉽다. 상권 톡방에 붙여넣는 텍스트라 줄 간격이 바뀌면 받는 사람이 알아챈다.

## 범위 밖

- **Supabase 스키마 변경과 과거 기록 마이그레이션.** `calculation_result`가 JSON 컬럼이라 키 추가는 그대로 저장된다. 부산·기타·마가 없는 과거 기록은 그대로 둔다.
- **ADR.** 전환·추가주문 칸은 숫자 위치로 저장되어 되돌릴 수 없었지만(`docs/adr/0001-order-columns-are-append-only.md`), 점유비는 키 기반 JSON이라 항목을 빼도 과거 기록의 자리가 어긋나지 않는다. 되돌리기 어려운 결정이 아니다.
- **전환·추가주문 칸 변경.** 이번 요청은 점유비만 건드린다. 부산은 전환·추가주문 칸에 추가하지 않는다.
- **담당자 보고문의 타사 큐레이션 재설계.** 진로와 참이슬을 하이트진로 한 줄로 합치는 식의 개편은 하지 않는다. R5 참조.
- **`대선(C1포함)` 라벨 변경.** 부산이 빠지면서 이름과 내용이 오히려 맞아떨어지므로 그대로 둔다.
- **푸시와 병합 시점.** 작업은 워크트리에서 하고 태스크마다 커밋한다. `main` 병합과 원격 반영은 사용자가 지시할 때 한다.

## 수용 기준

- [ ] 대선주조 입력란에 부산 칸이 대선(C1포함) 다음, 기타 앞에 나온다
- [ ] 무학 입력란 마지막과 롯데 입력란 마지막에 기타 칸이 있다
- [ ] `마. 기타 주류회사` 섹션 제목 오른쪽 같은 줄에 입력 칸이 있고, 항목 이름은 표시되지 않는다
- [ ] 마에 숫자를 넣으면 총 테이블 수가 그만큼 늘고, 모든 회사 백분율의 합이 100%가 된다
- [ ] 상권 보고문의 `마. 기타 주류회사` 줄이 한 줄이며 하위 항목 줄이 없다
- [ ] 상권 보고문과 화면 결과의 모든 테이블 단위가 대문자 `T`다
- [ ] 새 항목을 모두 0으로 둔 상권 보고문이 R6의 세 가지를 빼면 변경 전과 글자 단위로 같다
- [ ] 담당자 보고문에 `부산 : ` 줄이 `대선(C1포함) : ` 바로 다음에 있다
- [ ] 담당자 보고문에 어느 회사의 기타 줄도 없고 `마. 기타 주류회사`도 없다
- [ ] 담당자 보고문의 `좋은데이 톡시리즈`와 `갈매기` 문구가 그대로 남아 있다
- [ ] 담당자 보고문의 대선 줄과 부산 줄을 더한 값이 상권 보고문의 `다. 대선주조` 합계에서 기타를 뺀 값과 일치한다

## 검증

테스트가 없는 프로젝트입니다. 다음으로 검증합니다.

1. `npm run build`를 통과시킨다. `utils/getSupabaseClient.ts`가 모듈 로드 시점에 환경변수를 읽으므로 더미 값이 든 `.env.local`이 필요하다.
2. 변경 전 `main`에서 상권 보고문 기준값을 뽑아 두고, 변경 후 같은 입력으로 다시 뽑아 R6의 세 가지 외에 차이가 없음을 문자열 비교로 확인한다.
3. 개발 서버를 띄우고 브라우저 자동화로 클립보드에 실제로 들어가는 문자열을 확인한다. 화면에 보이는 것과 복사되는 것이 다를 수 있으므로 복사 텍스트를 직접 읽는다.
4. 광안 상권을 골라 담당자 보고문 복사 텍스트도 같은 방식으로 확인한다. 담당자 보고문은 광안에서만 나온다.
